# 📡 FollowUp Radar — ระบบจัดลำดับความสำคัญและติดตามผู้เรียน
### โครงการนำร่อง TIIS (ภารกิจที่ 2 — สอดคล้องตามภารกิจที่ 1)

---

## 📌 1. ภาพรวมโครงการและโครงสร้างโปรเจกต์
ระบบ **FollowUp Radar** พัฒนาขึ้นเพื่อแก้ปัญหาใน **ภารกิจที่ 1**:
- **กลุ่มเป้าหมาย:** นักศึกษาและผู้เริ่มต้นทำงานจำนวน **60 คน** ในโครงการพัฒนาทักษะระยะเวลา **6 สัปดาห์**
- **กรอบเวลาและงบประมาณ:** งบดำเนินงาน 30,000 บาท มี **ทีมหลัก 3 คน** และต้องติดตามผลหลังกิจกรรมหลัก **อย่างน้อย 14 วัน**
- **สแต็กเทคโนโลยี:**
  - **Frontend:** Next.js (App Router) ที่ `http://localhost:3000`
  - **Backend:** Node.js & Express.js ที่ `http://localhost:5000`
  - **Database:** Supabase PostgreSQL (`https://cwglopfaevserbrmcgpw.supabase.co`) พร้อมระบบ Hybrid In-Memory Data Store ป้องกันข้อผิดพลาด

## 🎯 3. การตอบโจทย์เงื่อนไขจากภารกิจที่ 1

| ข้อกำหนดในภารกิจที่ 1 | วิธีการที่ต้นแบบ FollowUp Radar นำมาแก้ไข |
|---|---|
| **ปัญหา:** ทีมหลัก 3 คนไม่รู้ว่าใครควรติดต่อก่อน | ระบบคำนวณและแสดงผลใน **หน้าจอเดียว (Single Screen)** ดันกลุ่มเสี่ยงสูงขึ้นมาอันดับแรกทันที |
| **สัญญาณความเสี่ยง 4 ประการ:** ขอความช่วยเหลือ, ยังไม่เริ่ม, ขาดรายงาน, ติดอุปสรรค | `priorityEngine.js` นำสัญญาณทั้ง 4 มาประเมินถ่วงน้ำหนักและแสดงผลชัดเจนบนการ์ด |
| **ติดตามผลอย่างน้อย 14 วัน** | แถบแสดงความคืบหน้า 14-day timeline tracker และสถานะ: *รอติดต่อ ➡️ ติดต่อแล้ว ➡️ ปิดเรื่อง* |
| **ผู้ดูแลที่ใช้มือถือเป็นหลัก** | ออกแบบการ์ดแบบ Responsive Card ต่อคนบนจอแคบ ไม่ต้องเลื่อนตารางแนวนอน |
| **ผู้ดูแลที่ไม่ถนัดเทคนิค** | ใช้ภาษาไทยสั้น กระชับ ชัดเจน เช่น *"รอติดต่อ"*, *"ติดต่อแล้ว"*, *"ปิดเรื่อง"* |
| **ผู้ที่แยกสีไม่ชัด (Colorblind)** | ป้ายระดับความสำคัญมีทั้ง **ไอคอน + ข้อความกำกับ + สี** (เช่น 🚨 เร่งด่วนมาก, ⚠️ ควรติดตาม) |
| **ผู้เรียนที่ไม่มั่นใจ** | แสดงเป็น *"ควรติดตาม"* ไม่ใช่คะแนนตัดสินความสามารถ และให้ทีมเป็นผู้ตัดสินใจขั้นสุดท้าย |
| **ข้อมูลไม่ครบ** | ระบบขึ้นเตือน *"ต้องตรวจสอบข้อมูล"* แทนการสรุปผิดว่าผู้เรียนเป็นผู้มีปัญหา |

## 🧪 4. ผลการทดสอบ 4 กรณี (Test Cases Report)

ระบบผ่านการทดสอบครบถ้วนทั้ง 4 กรณี (รันได้ผ่านปุ่ม **"🧪 รันชุดทดสอบ 4 กรณี"** บนหน้าเว็บ หรือคำสั่ง `npm test` ในโฟลเดอร์ `backend`):

1. **กรณีปกติที่ 1 (Normal Case 1: Priority Calculation & Display)**:
   - ทดสอบดึงรายชื่อผู้เรียนครบ 60 คน
   - ผู้เรียนกลุ่มวิกฤต (เช่น LN-001 กิตติศักดิ์ ซึ่งขอความช่วยเหลือและขาดรายงาน 4 วัน) ได้รับการจัดลำดับขึ้นมาเป็น **"🚨 เร่งด่วนมาก"** พร้อมเหตุผลภาษาไทยชัดเจน
   - ผู้เรียนที่ข้อมูลไม่ครบ ได้รับการติดป้าย **"🔍 ต้องตรวจสอบข้อมูล"** อย่างถูกต้อง
   - **ผลลัพธ์:** ✅ ผ่าน (PASSED)

2. **กรณีปกติที่ 2 (Normal Case 2: Follow-up & 14-Day Status Progression)**:
   - บันทึกการติดต่อผู้เรียน (LN-001) ผ่านโทรศัพท์ และเปลี่ยนสถานะจาก *"รอติดต่อ"* เป็น *"ติดต่อแล้ว"*
   - บันทึกปิดเรื่องสำเร็จเมื่อผู้เรียนบรรลุผลลัพธ์ใน 14 วัน เป็น *"ปิดเรื่อง"*
   - ตรวจสอบประวัติ Log ย้อนหลังได้ทันที
   - **ผลลัพธ์:** ✅ ผ่าน (PASSED)

3. **กรณีผิดพลาดที่ 1 (Error Case 1: Incomplete / Invalid Submission)**:
   - พยายามส่งบันทึกการติดตามโดยไม่ระบุรายละเอียด หรือข้อความสั้นกว่า 5 ตัวอักษร
   - ระบบปฏิเสธพร้อมส่ง HTTP 400 และแสดงข้อความเตือนเป็นภาษาไทยชัดเจน ป้องกันข้อมูลเสียหาย
   - **ผลลัพธ์:** ✅ ผ่าน (PASSED)

4. **กรณีผิดพลาดที่ 2 (Error Case 2: Duplicate Entry Prevention)**:
   - พยายามกดบันทึกซ้ำซ้อนติดต่อกันทันทีด้วยข้อความเดียวกัน
   - ระบบตรวจจับความซ้ำซ้อนและปฏิเสธด้วย HTTP 409 พร้อมแจ้งเตือนผู้ใช้งานทันที ป้องกันไม่ให้ทีมงาน 3 คนบันทึกงานซ้ำซ้อน
   - **ผลลัพธ์:** ✅ ผ่าน (PASSED)

### ตัวอย่าง ก่อน - หลัง การใช้งาน (Before & After Example)
- **ก่อนติดตาม (Before):** ผู้เรียน LN-001 (กิตติศักดิ์) ติดอุปสรรคการดูบทเรียนบนมือถือ ขาดส่งงาน 4 วัน สถานะเป็น *"รอติดต่อ"* และเสี่ยงที่จะหลุดจากโครงการโดยทีมงานไม่ทราบ
- **หลังติดตาม (After):** ระบบดันขึ้นมาเป็นเคสเร่งด่วน ทีมงาน 1 โทรศัพท์ติดต่อให้คำแนะนำและส่งคู่มือฉบับย่อบนมือถือ ผู้เรียนส่งงานสำเร็จและระบบเปลี่ยนสถานะเป็น *"ปิดเรื่อง"* ครบถ้วนตามเป้าหมาย 14 วัน

### ข้อจำกัดที่ยังเหลือในปัจจุบัน (Remaining Limitations)
- การแจ้งเตือนยังเป็นการแสดงผลผ่านหน้าจอเรดาร์ของระบบ ในอนาคตสามารถพัฒนา Webhook ส่งข้อความแจ้งเตือนเข้าห้อง LINE ของทีมหลัก 3 คนได้โดยตรง

## 🚀 5. วิธีเปิดใช้งานระบบ (How to Run)

### 1) รัน Backend (Node.js & Express)
```bash
cd backend
npm install
npm run dev
# เซิร์ฟเวอร์จะเริ่มทำงานที่ http://localhost:5000
```

### 2) รัน Frontend (Next.js)
```bash
cd frontend
npm install
npm run dev
# หน้าเว็บจะเริ่มทำงานที่ http://localhost:3000
```
